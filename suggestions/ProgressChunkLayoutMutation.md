# Updating repeated progress chunks after layout

WinXPSkin initially bound a `RepeatStack.ItemSource` range directly to the progress fill's `CachedBounds`. Moving the tracker from zero to a partial value rebuilt the stack during the layout bounds traversal. The first added `ProgressChunkTemplate` contained a two-row percentage table whose row options existed but whose measured row-size array was still empty. Under the Debug x64 native Direct2D hosted test, PID 4572 stopped with a second-chance C++ exception in `GuiTableComposition::Layout_UpdateCellBoundsPercentages`: `dimOptions.Count() == 2`, `dimSizes.Count() == 0`, and the available dimension was 14 pixels. The indexed write failed before the application could render the new chunks.

The relevant implementation is [GacUI/Source/GraphicsComposition/GuiGraphicsTableComposition.cpp](https://github.com/vczh-libraries/GacUI/blob/master/Source/GraphicsComposition/GuiGraphicsTableComposition.cpp). The event documentation in `GacUI/.github/KnowledgeBase/manual/gacui/components/compositions/events.md` describes deferred composition restructuring as the safe pattern. Creating or deleting repeated children synchronously in a bounds notification can introduce a new table after the current measurement phase.

The local fix keeps the requested count calculation in an XML binding. A coalesced `GuiApplication.InvokeInMainThread` callback publishes that count to a second property after current layout/event processing returns. Only the published property drives `RepeatStack.ItemSource`; the segment table, gradients, sizing and spacing remain XML.

Each callback captures an independent shared lifetime token. The template destructor marks the token inactive before teardown, and the callback checks that token before accessing the template. It clears its queued flag before publishing the latest requested count so a later or reentrant request can schedule another update. This also avoids relying solely on `INativeDelay.Cancel`: [GacUI/Source/Utilities/SharedServices/GuiSharedAsyncService.cpp](https://github.com/vczh-libraries/GacUI/blob/master/Source/Utilities/SharedServices/GuiSharedAsyncService.cpp) marks due delays Executing before running ordinary queued tasks, so a queued template refresh could destroy the template before a noncancelable due callback runs.

An upstream improvement would detect structural changes during bounds traversal and restart measurement before arranging newly added tables, or reject the mutation with an explanatory diagnostic. Regression coverage should include changing zero/partial/full progress, resizing, fast value changes, switching skins with an update pending, and destroying the containing view before a queued callback executes. No upstream source is modified.
