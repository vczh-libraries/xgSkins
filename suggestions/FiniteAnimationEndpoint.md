# Finite animations omit their endpoint

Win7Skin button transitions stopped at intermediate colors after their 120 ms
duration. Waiting ten seconds did not change the result. For example, a normal
enabled button retained gradient colors `#F9F9F9`, `#ECECEC`, `#E1E1E1`, and
`#D5D5D5` with text `#141414`, instead of the palette's `#FAFAFA`, `#EBEBEB`,
`#DDDDDD`, `#CFCFCF`, and black text. Hover transitions also retained
intermediate colors.

## Upstream cause

In
[GacUI-repo/Source/Controls/Templates/GuiAnimation.cpp](https://github.com/vczh-libraries/GacUI/blob/master/Source/Controls/Templates/GuiAnimation.cpp),
`GuiFiniteAnimation::Run` invokes its callback only while `currentTime < length`.
At or after the duration, it skips the callback and `GetStopped` becomes true.
The root timer removes the animation immediately. Consequently the final
callback never receives the animation's duration.

The XML `Gradient` generated by
[GacUI-repo/Source/Compiler/GuiInstanceAnimation.cpp](https://github.com/vczh-libraries/GacUI/blob/master/Source/Compiler/GuiInstanceAnimation.cpp)
only calls `Interpolate(currentTime / time)` from that callback; it performs no
separate endpoint transfer. The imported runtime and generated Win7Skin C++
have these same behaviors. The skin follows the documented XML animation API.

## Local workaround

Win7Skin and Win8Skin keep their XML `Gradient` resources and linear 120 ms duration.
One small Workflow coroutine helper, `CompleteColorAnimation` in
`Template_Button.xml`, wraps the animations. Its parameters are an
`IGuiAnimation^` and a completion callback. The helper's signature uses only
existing metadata types because generated XML `Gradient` types are unavailable
during the earlier script compilation pass.

Every call evaluates the original builder's `CreateAnimation` immediately,
capturing the current colors and new target before passing the resulting inner
animation to the helper. The helper plays and waits for that animation, then
invokes the supplied callback to call `builder.Interpolate(1.0)`. The template stores the
wrapper in `lastAnimation`, so interrupting a transition kills the wrapper and
its inner animation together. The cancelled coroutine never reaches its final
transfer; the replacement transition begins from the current intermediate
colors without snapping to the old target. No upstream or imported source is
modified.

## Proposed upstream correction and regression

On the completion tick, invoke the finite callback with
`min(elapsedTime, length)` before reporting completion. Ensure the endpoint is
delivered exactly once, including when the first timer tick occurs after the
duration. A zero-duration animation should complete on its first run and invoke
its callback with zero; XML `Gradient` must handle zero duration explicitly
rather than dividing zero by zero, applying the target state directly.

Add regressions for an exact-duration tick, an overshooting tick, a first tick
after the duration, and zero duration. Assert the final color equals the target
exactly. Also interrupt one transition halfway through and start a replacement:
the cancelled target must never be applied, and the replacement must begin from
the intermediate state and reach its own endpoint. Exercise pause/resume so
elapsed-time accounting remains correct. Remove the skin-local completion
wrappers after the imported runtime guarantees this behavior.
